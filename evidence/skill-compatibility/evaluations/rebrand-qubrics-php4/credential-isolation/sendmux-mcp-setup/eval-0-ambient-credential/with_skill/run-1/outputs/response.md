Prepare only; launch no server/client and retrieve no credentials. Construct an allowlisted child launch environment, excluding inherited QUBRICS_* and SENDMUX_* values, then reintroduce only intended secret-backed values. Preserve the authorised SENDMUX_API_KEY source privately before rebuilding that environment. Remove both prefixes' generic API keys, per-surface API keys, HTTP bearer tokens and API base-URL overrides: QUBRICS values outrank SENDMUX fallbacks, and a per-surface key can override a generic key.

For Mailbox-only, set only SENDMUX_API_KEY to the intended mbx_support credential and prepare sendmux-mcp-mailbox. For combined sendmux-mcp, explicitly choose surfaces and supply separate SENDMUX_MAILBOX_API_KEY, SENDMUX_MANAGEMENT_API_KEY and SENDMUX_SENDING_API_KEY only when their intended credentials and surfaces are authorised. The supplied mailbox credential cannot stand in for a Management root key or establish Sending permission. Do not enable missing surfaces. Use only approved upstream endpoints.

Local HTTP needs a separately sourced MCP_HTTP_BEARER_TOKEN under the chosen prefix; it protects the local/private MCP endpoint and is not the upstream API key. Isolate clients too, keeping bearer/API values out of arguments, output and checked-in configuration. No client was selected: describe setup in prose, not generic client JSON. Hosted OAuth uses its own resource, not a REST token.
